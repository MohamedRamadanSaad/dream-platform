# BACKEND SPEC — إلى سعادة الدارين (Spring Boot)

This is the binding specification for `backend/`. The frontend already exists and is the **contract**:
- `frontend/src/api/types.ts` — every DTO field name, enum value and shape. Match them exactly (camelCase JSON).
- `frontend/src/api/endpoints.ts` — every route + method + query/body.
- `frontend/src/mocks/handlers.ts` — the reference behaviour (status transitions, error codes, what each route returns). When in doubt, do what the mock does.
- `docs/API_CONTRACT.md` — the 10 non-negotiable rules.

## 0. Stack & conventions
- Java 21, Spring Boot **3.3.5**, Gradle **Kotlin DSL** (`build.gradle.kts`, `settings.gradle.kts`), no Gradle wrapper committed (CI installs Gradle; `gradle` is on PATH).
- Dependencies: spring-boot-starter-{web,security,data-jpa,validation,actuator,thymeleaf,mail,oauth2-resource-server is NOT used}, flyway-core + flyway-database-postgresql, postgresql driver, `com.auth0:java-jwt:4.4.0`, `com.google.api-client:google-api-client:2.7.0` (Google ID token verify), `com.bucket4j:bucket4j_jdk17-core:8.14.0` (rate limit), `nl.martijndwars:web-push:5.1.1` + `org.bouncycastle:bcprov-jdk18on:1.78.1`, `org.springdoc:springdoc-openapi-starter-webmvc-ui:2.6.0`, `io.sentry:sentry-spring-boot-starter-jakarta:7.16.0`, Lombok (compileOnly + annotationProcessor), test: spring-boot-starter-test, spring-security-test, `org.testcontainers:postgresql:1.20.3` + `junit-jupiter`, `com.icegreen:greenmail-junit5:2.1.0` (SMTP tests optional).
- Base package `com.saadat`. Layering per feature package: `api` (controllers + request/response records), `domain` (entities, enums), `repo`, `service`, `event` when needed. Cross-cutting in `com.saadat.common.*` and `com.saadat.config.*`.
- **All route strings live in `com.saadat.common.api.ApiPaths`** (public static final Strings, grouped by nested classes: `Auth`, `Public`, `Me`, `Dreams`, `Checkout`, `Notifications`, `Push`, `Youtube`, `Admin`, `Webhooks`). Controllers use `@RequestMapping(ApiPaths.Dreams.ROOT)` etc. No literal paths in controllers or security config.
- **No business string/number literals in code.** Anything configurable (SLA hours, magic-link TTL, draft limit, prices fallback, YouTube channel id, brand name, support email, base URLs…) is either an env-backed `@ConfigurationProperties` (infrastructure: secrets, URLs) or a row in `app_settings` (business settings the interpreter may change) read through `SettingsService`. Keys are constants in `com.saadat.settings.SettingKeys`.
- DTOs are Java `record`s. Entities use Lombok `@Getter @Setter @NoArgsConstructor` (+ `@Builder` where handy), UUID ids (`@Id @GeneratedValue(strategy = UUID)` or `UUID.randomUUID()` in constructor), `Instant` timestamps, enums stored as `@Enumerated(EnumType.STRING)`.
- Errors: RFC 7807 via `ProblemDetail` from a single `@RestControllerAdvice` (`com.saadat.common.error.ApiExceptionHandler`). Domain exceptions: `NotFoundException`(404), `ConflictException`(409), `ForbiddenException`(403), `PaymentRequiredException`(402, sets `code: "INSUFFICIENT_CREDITS"` property), `ValidationException`(422), plus Bean Validation → 400 with `errors` map. Every problem has `type = https://api.saadatu-aldarein.com/errors/<slug>`.
- Profiles: `local` (docker-compose Postgres on localhost:5432, mock payment provider, mail to MailHog/log, mocks for Google token), `dev` (staging server, real SMTP, Kashier **test** keys), `prod`. Files: `application.yml` (shared), `application-local.yml`, `application-dev.yml`, `application-prod.yml`. Everything secret comes from env vars with sensible local defaults ONLY in `application-local.yml`.
- Time zone for schedules: `Africa/Cairo` (setting). Locale for emails: user's `locale`.
- Logging: JSON in prod (logback-spring.xml), correlation id filter (`X-Request-Id`), never log tokens/emails in full.

## 1. Data model — Flyway `V1__…` … in `src/main/resources/db/migration`
Use PostgreSQL types; `timestamptz`; `uuid` PKs; enums as `varchar` + CHECK constraint. One migration per aggregate group, numbered:

- `V1__settings.sql`: `app_settings(key varchar PK, value text, type varchar(16) CHECK in ('STRING','INT','BOOL','JSON'), description text, updated_at, updated_by uuid null)` + seed rows (see §2).
- `V2__users_auth.sql`: `users(id, email citext/varchar unique lower, name, gender null, role, locale, country_code char(2) null, country_source varchar(16) null, onboarded bool, marketing_opt_in bool default false, created_at, last_login_at, deleted_at null)`; `auth_identities(id, user_id fk, provider, provider_subject, created_at, last_used_at, unique(provider, provider_subject))`; `magic_links(id, email, token_hash unique, code_hash, expires_at, used_at, created_ip, created_at)`; `refresh_tokens(id, user_id, token_hash unique, family_id uuid, expires_at, revoked_at, user_agent, created_at)`; `user_sessions(id, user_id, country_code, user_agent, started_at)`; indexes on user_id/expires.
- `V3__geo_pricing.sql`: `countries(code char(2) PK, name_ar, name_en, continent char(2), default_currency char(3), group_id uuid null)`; `country_groups(id, name, created_at)`; `packages(id, name_ar, name_en, description_ar, description_en, credits int, badge, sort_order, active, validity_months null, created_at, updated_at)`; `price_rules(id, scope, scope_id varchar null, package_id fk, price numeric(12,2), currency char(3), unique(scope, scope_id, package_id))`; `promotions(id, name, package_ids uuid[], type, value numeric, starts_at, ends_at, max_uses null, used_count, scope, scope_id null, active)`; `coupons(id, code unique upper, type, value, max_uses null, per_user_limit int, used_count, expires_at null, active)`; `coupon_redemptions(id, coupon_id, user_id, order_id, created_at, unique(coupon_id, user_id, order_id))`. Seed ~60 countries (all Arab countries + EU + NA + key others) with continent & default currency, the two groups from the mock (الخليج, المغرب العربي), 3 packages, and the price rules from `frontend/src/mocks/data.ts`.
- `V4__orders_credits.sql`: `orders(id, user_id, product_type varchar default 'DREAMS', package_id, package_name_snapshot, credits int, amount numeric, currency, discount numeric default 0, coupon_id null, promotion_id null, price_rule_scope, provider, provider_order_id null, provider_txn_id unique null, status, failure_reason null, checkout_intent jsonb null, country_code, country_source, card_country null, created_at, paid_at null, expires_at)`; `credit_ledger(id, user_id, delta int, reason, order_id null, dream_id null, created_by uuid null, note null, created_at)`; index (user_id, created_at).
- `V5__dreams.sql`: `dreams(id, user_id, gender, status, text, created_at, updated_at, submitted_at null, sla_hours_snapshot int null, expected_by null, sla_paused_at null, interpreted_at null, cancelled_reason null, ledger_entry_id null, assignee_id null)`; `dream_messages(id, dream_id, sender_role, body, created_at, read_at null)`; `interpretations(id, dream_id unique, interpreter_id, text, created_at)`; `testimonials(id, dream_id unique, user_id, rating int check 1..5, comment, approved bool default false, created_at)`; indexes (user_id, created_at desc), (status, submitted_at).
- `V6__notifications.sql`: `notifications(id, user_id, type, title, body, link, created_at, read_at)`; `push_subscriptions(id, user_id, endpoint unique, p256dh, auth, user_agent, created_at, last_success_at, failures int)`; `email_log(id, user_id null, to_email, template, subject, status, provider_id null, error null, created_at)`.
- `V7__youtube.sql`: `youtube_videos(id varchar PK /*video id*/, title, published_at, thumbnail_url, url, fetched_at)`; `youtube_seen(user_id PK, seen_at)`.
- `V8__audit_interpreter.sql`: `audit_log(id, actor_id, action, entity, entity_id, before jsonb, after jsonb, created_at)`; `user_notes(user_id PK, notes text, tags text[], updated_at)`; `interpreter_settings` is NOT a table — it lives in `app_settings` (busy mode etc.).

Interpreter account: on first login, if email ∈ setting `interpreter.emails` (comma list) → role INTERPRETER.

## 2. Settings (`com.saadat.settings`)
`SettingsService` with typed getters (`getString/getInt/getBool/getJson`), 60s cache, `PUT` invalidates. Seed keys (`SettingKeys`):
`brand.name.ar`, `brand.name.en`, `brand.tagline.ar`, `brand.tagline.en`, `brand.support_email`, `brand.youtube_url`, `brand.youtube_channel_id` (empty until provided), `wait.busy` (false), `wait.normal_hours` (48), `wait.busy_min_days` (2), `wait.busy_max_days` (3), `wait.message_ar`, `wait.message_en`, `wait.auto_reset_at` (null), `dreams.min_chars` (20), `dreams.max_chars` (4000), `dreams.draft_limit` (20), `dreams.reply_reminder_hours` (48), `dreams.testimonial_request_days` (7), `auth.magic_ttl_minutes` (15), `auth.access_ttl_minutes` (15), `auth.refresh_ttl_days` (30), `orders.expire_minutes` (30), `interpreter.emails` (`fatema@saadatu-aldarein.com`), `interpreter.digest_hour` (9), `pricing.global_currency` (USD), `youtube.poll_minutes` (30).
Admin endpoints `GET/PUT /admin/settings` (map) exist for the interpreter; `admin/wait-time` reads/writes the `wait.*` keys and maps to `WaitTimeSettings` DTO.

## 3. Security (`com.saadat.config.SecurityConfig`, `com.saadat.auth`)
- Stateless; JWT HS256 access token (`sub`=userId, `role`, `email`), TTL from settings; refresh token random 32 bytes, stored SHA-256, rotated on use, **reuse detection revokes the whole family**; cookie `rt`: HttpOnly, Secure (not in local), SameSite=Lax, Path=`/api/auth`.
- Open: `ApiPaths.Auth.*`, `ApiPaths.Public.*`, `ApiPaths.Webhooks.*`, `/actuator/health`, `/v3/api-docs/**`, `/swagger-ui/**`. `/admin/**` → `hasRole('INTERPRETER')`. Everything else authenticated.
- CORS from `app.frontend-url` (+ `http://localhost:5173` in local).
- Bucket4j filter: 10/min/IP on `/auth/**`, 30/min/user on `POST /dreams`, 5/min/IP on `/checkout`.
- Google: verify `idToken` with `GoogleIdTokenVerifier` (audience = `app.google.client-id`); require `email_verified=true`; upsert user by lowercase email; link identity (GOOGLE, sub). In `local` profile, `idToken == "mock"` logs in the seeded user (guarded by property `app.auth.allow-mock=true` only in local).
- Magic link: `POST /auth/magic/request` always 204; generates token (32B url-safe) + 6-digit code, stores hashes, sends email with both link `${frontend}/auth/callback?token=…` and code. `POST /auth/magic/verify` accepts `{token}` or `{email, code}`; single use; creates user if absent (`onboarded=false`, name ''), links MAGIC_LINK identity.
- `POST /auth/onboarding` sets name/gender/onboarded. `PUT /me/preferences` per DTO.
- Country: `CountryResolver` reads `CF-IPCountry` header (fallback `X-Country` in local, else setting default `SA`); stored on user at first login (`country_source=IP`); user cannot change it (only admin). Each `user_sessions` row on login/refresh.

## 4. Pricing & catalog (`com.saadat.pricing`)
`PriceResolver.resolve(countryCode, packageId)` → COUNTRY → GROUP → CONTINENT → GLOBAL, returns price, currency, scope. `PromotionService.apply(pkg, price, country)` (active window, scope match, max_uses). `GET /public/catalog` uses the caller's country (auth user's stored country, else header). Admin CRUD for packages, price-rules (POST upserts by (scope,scopeId,packageId)), country-groups (moving a country between groups updates `countries.group_id`), promotions, coupons — shapes in types.ts.

## 5. Orders, checkout, payments (`com.saadat.payments`)
- `PaymentProvider` interface: `createCheckout(Order) → CheckoutResponse`, `parseWebhook(HttpServletRequest, body) → WebhookEvent{providerTxnId, providerOrderId, success, amount, currency, cardCountry, raw}`, `verifySignature(...)`. Implementations: `KashierProvider` (EGP), `MorProvider` (SAR/USD — stub that throws `NotConfigured` until keys exist, plus `MockPaymentProvider` used in `local`/`dev` when `app.payments.mock=true`: returns `checkoutUrl = ${frontend}/checkout/mock/{orderId}` and exposes `POST /webhooks/mock/{orderId}?success=true` (only when mock enabled) that fires the same internal `PaymentConfirmed` path).
- Kashier (payment sessions): `POST {https://test-api|https://api}.kashier.io/v3/payment/sessions` with headers `Authorization: <Secret Key>`, `api-key: <Payment API Key>`, body `{merchantId, order=order.id, amount "49.00", currency, expireAt=order.expiresAt, maxFailureAttempts 3, type one-time, allowedMethods card,wallet, display ar|en, merchantRedirect=${frontend}/me/payments, failureRedirect true, serverWebhook=${api}/webhooks/kashier, customer{email, reference=userId}}` → `{_id, sessionUrl}`; checkoutUrl = `sessionUrl`. Webhook JSON `{event, data}`: sort `data.signatureKeys`, build `key=urlEncodedValue&…`, HMAC-SHA256 with the Payment API Key, compare to header `x-kashier-signature`. Only `event=pay` + `data.status=SUCCESS` calls `confirm` (failed tries are acknowledged and ignored — the customer may retry inside the session; unpaid orders expire). Kashier sends no card-issuer country. Kashier currencies: EGP, USD, EUR, GBP (no SAR). Config: `app.payments.kashier.{merchant-id,api-key,secret-key,mode,base-url}`.
- `POST /checkout {packageId, couponCode?, dreamIds?}`: price from `PriceResolver` + promotion + coupon (validate active/expiry/max/per-user) computed **server-side**; create `orders` row (INITIATED, `checkout_intent = {dreamIds}`, `expires_at = now + orders.expire_minutes`, `country_code = user.country`), then provider.createCheckout. Never trust client amounts.
- Webhook handling (`PaymentService.confirm`): verify signature → find order by provider order id / merchant_order_id → idempotent on `provider_txn_id` unique (duplicate → 200 no-op) → amount & currency must equal order (else status SUSPICIOUS, audit, notify interpreter) → card country vs order country mismatch → SUSPICIOUS → else status SUCCESS, `paid_at`, ledger +credits (reason PURCHASE), publish `PaymentSucceededEvent`; then auto-submit `checkout_intent.dreamIds` via `DreamService.submit(userId, ids, orderId)` ignoring ones no longer DRAFT.
- `@Scheduled` every 5 min: INITIATED past `expires_at` → EXPIRED.
- `GET /me/orders`, `GET /me/orders/{id}`, admin `GET /admin/orders` (+userName).

## 6. Credits & dreams (`com.saadat.credits`, `com.saadat.dreams`)
- Balance = SUM(delta) for user. `CreditService.consume(userId, n, reason, dreamId, orderId)` runs in a transaction that first does `SELECT id FROM users WHERE id=? FOR UPDATE`, re-reads balance, throws `PaymentRequiredException(missing)` if short.
- Dreams: DRAFT create/update/delete (only DRAFT editable; min/max chars from settings; draft_limit). `POST /dreams/submit {dreamIds}`: all must be caller's DRAFTs (else 409); consume credits atomically; set IN_REVIEW, `submitted_at`, `sla_hours_snapshot` (busy ? busy_max_days*24 : normal_hours), `expected_by`, `ledger_entry_id`; notify user (DREAM_RECEIVED) + interpreter (DREAM_SUBMITTED). Response `{submitted, remainingCredits}`.
- Messages: interpreter `POST /admin/dreams/{id}/messages` only from IN_REVIEW → AWAITING_USER_REPLY, `sla_paused_at=now`, notify user (INTERPRETER_QUESTION); user `POST /dreams/{id}/messages` only from AWAITING_USER_REPLY → IN_REVIEW, extend `expected_by` by paused duration, notify interpreter (USER_REPLIED). `GET /dreams/{id}` marks interpreter messages read; admin GET marks user messages read.
- Interpretation: `POST /admin/dreams/{id}/interpretation` from IN_REVIEW or AWAITING_USER_REPLY → INTERPRETED, `interpreted_at`, notify user (INTERPRETATION_READY). `POST /admin/dreams/{id}/cancel {reason}` → CANCELLED + ledger refund (+1, reason REFUND).
- Testimonial: only INTERPRETED, owner, once; `approved=false`. Admin list/patch. `GET /public/testimonials` approved only, first name only.
- Admin queue `GET /admin/dreams?status=` sorted `submitted_at asc`, `slaDeadline=expected_by`, `overdue = status==IN_REVIEW && now>expected_by`. `GET /admin/dreams/{id}` includes `user{}` and `payment{}` (from ledger_entry → order).
- Scheduled: reply reminder email after `dreams.reply_reminder_hours` in AWAITING_USER_REPLY (once); testimonial request email `dreams.testimonial_request_days` after INTERPRETED if no testimonial (once, track via email_log template+dream link); interpreter daily digest at `interpreter.digest_hour` Cairo.

## 7. Notifications, email, push (`com.saadat.notifications`, `com.saadat.mail`, `com.saadat.push`)
- `NotificationService.notify(userId, type, title, body, link)` → row + async push to all subscriptions + (per type) email. Types per types.ts. Titles/bodies come from `messages_ar.properties`/`messages_en.properties` (MessageSource) keyed `notif.<TYPE>.title/body` — not string literals.
- Email: `MailService.send(to, template, locale, model)` renders Thymeleaf `templates/mail/<template>_<locale>.html` (fallback `_ar`), subject from messages, sends via `JavaMailSender` (SMTP config from env: host, port, user, pass, from name/address), logs to `email_log`, retries 3× with backoff (`@Retryable` or manual). In `local`, if SMTP host empty → log the rendered HTML to console and mark status LOGGED.
- Templates (both `_ar` RTL and `_en` LTR), brand styling: night `#0A1128` header band with gold `#D4AF37` brand line, pearl `#F4EFE6` body, IBM Plex Sans Arabic via Google Fonts link (email-safe fallbacks), one gold CTA button, footer with YouTube link + support email; all copy from the model/messages, no literals in Java:
  `magic-link` (link + 6-digit code), `dream-received` (expected date + wait message), `interpreter-question`, `user-replied` (to interpreter), `interpretation-ready` (link only, no text), `payment-receipt` (package, amount, currency, ref, credits), `payment-suspicious` (to interpreter), `reply-reminder`, `testimonial-request`, `interpreter-digest` (N waiting, M overdue), `dream-submitted` (to interpreter), `youtube-new-video` (opt-in later; template only).
- Push: VAPID keys from env (`app.push.public-key/private-key/subject`); `POST/DELETE /push/subscriptions`; send JSON `{title, body, url}`; on 404/410 delete subscription. Also expose `GET /public/push-key` returning the public key.
- `GET /notifications`, `POST /notifications/read-all`, `POST /notifications/{id}/read`.

## 8. YouTube as a notification (`com.saadat.youtube`)
- Poll `https://www.youtube.com/feeds/videos.xml?channel_id={brand.youtube_channel_id}` every `youtube.poll_minutes` (skip if id empty); upsert `youtube_videos`. Also admin `POST /admin/youtube/refresh`.
- `GET /youtube/unseen` (auth) → `{count, latest:[{id,title,url,publishedAt,thumbnailUrl}] (max 5)}` where count = videos with `published_at > youtube_seen.seen_at` (or all if none, capped at 9). `POST /youtube/seen` sets `seen_at=now`.
- Frontend will show the count on the YouTube button and call `/youtube/seen` on click (frontend change is out of scope for the backend agent; keep the shapes above).

## 9. Admin analytics (`com.saadat.admin.analytics`)
- `GET /admin/analytics/summary`, `GET /admin/analytics/countries?period=7d|30d|1y|all` (visits = distinct visits of the site pages from `page_views`, the same "visits" as the traffic report — not sign-ins; dreams from `dreams.submitted_at`, revenue converted to base currency USD with static rates from settings key `pricing.fx_to_usd` JSON `{ "EGP":0.0208,"SAR":0.2667,"USD":1 }`), `GET /admin/analytics/users?list=&q=&page=&size=`, `GET /admin/users/{id}` (AdminUser360 — note field `dreamList`), `PUT /admin/users/{id}/notes`, `POST /admin/users/{id}/credits {delta, reason}` (ledger MANUAL + audit).
- Audit: an `AuditService.record(actor, action, entity, id, before, after)` called by every admin mutation (prices, packages, promotions, coupons, settings, wait-time, manual credits, notes, testimonial approval, cancel).

## 10. Public
`GET /public/catalog`, `/public/wait-time` (uses Accept-Language for message), `/public/testimonials`, `/public/stats` (settings keys `stats.subscribers/views/videos`), `/public/push-key`.

## 11. Tests (must pass in CI)
- Testcontainers Postgres for `@SpringBootTest` slices; `@ActiveProfiles("test")` with `application-test.yml` (mock payments, mail logged, allow-mock auth).
- Unit: JWT issue/verify, refresh rotation + reuse detection, magic link single-use & expiry, `PriceResolver` precedence (country > group > continent > global), promotion/coupon math, Kashier webhook signature with the documented vector.
- Integration: submit with insufficient credits → 402 + code; concurrent submit (two threads, 1 credit) → exactly one succeeds; duplicate webhook is a no-op; amount mismatch → SUSPICIOUS and no credits; status machine rejections (409); admin-only routes 403 for USER.

## 13. Definition of done
`gradle build` green in CI; every route in `endpoints.ts` implemented with matching JSON; `docker compose` stack starts; a full flow works against the real API with `VITE_USE_MOCKS=false`: magic-link login (local) → onboarding → draft → checkout (mock provider) → mock webhook → credits → auto-submit → interpreter question → user reply → interpretation → testimonial → notification list + emails logged.
