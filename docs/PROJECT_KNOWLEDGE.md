## 1. What the product is

A dream-interpretation platform for the interpreter **المعبرة فاطمة** ("إلى سعادة الدارين"). Users buy credits (packages), submit dreams, and receive a written interpretation. The interpreter has a small admin dashboard. Everything is bilingual (Arabic default, RTL; English, LTR), dark/light, installable as a PWA with push notifications.

Core rules agreed with the owner (Mohamed Ramadan, m.ramadansaad@gmail.com):
- Payment **before** interpretation (credits). One credit = one dream.
- No passwords. Login = Google **or** magic link / 6-digit e-mail code. No Facebook/Apple for launch.
- Interpreter accounts = any e-mail ending with the site domain (`@saadatu-aldarein.com`) → role `INTERPRETER`, and they may only sign in with the e-mail code (Google is rejected with code `INTERPRETER_USE_MAGIC`). Also a list setting `interpreter.emails` and env `INTERPRETER_EMAILS` (bootstrap).
- Zero-trust geo pricing: the **server** decides the visitor's country (Cloudflare `CF-IPCountry` header, else the visitor's IP in the GeoIP database on the VPS); the user can never pick a cheaper country. Prices resolve COUNTRY → GROUP → CONTINENT → GLOBAL. Currencies: EGP (Egypt), SAR (Gulf group), USD (rest). The country of each payment is stored on the order; mismatches flag the order `SUSPICIOUS`.
- "Wait time" (مدة الانتظار) is a setting shown positively; the service never says "closed". Normal mode = N hours; busy mode = min–max days, with optional auto-reset date.
- Testimonials can only be written on **interpreted** dreams and need interpreter approval before showing publicly.
- Interpreter can ask follow-up questions (chat per dream); e-mails + in-app + push notifications on every step.
- YouTube channel button in the header doubles as a notification badge (count of videos the user hasn't seen).
- Promotions must be religiously appropriate (no "Mawlid"); current seeds: Saudi National Day (SA) and 6 October Victory (EG) — scoped by country.
- Every user has a date of birth (age shown to the interpreter), a gender, and an initial-letter colour avatar instead of photos.
- Design: calm, fancy, night-sky hero with moving star shapes, meteors, a moon that crosses the sky right→left changing phase (thin crescent → full at centre → crescent), hadith text "written in the sky" that brightens where the moon passes behind it, GSAP morph icons, text reveals. Fonts IBM Plex Sans Arabic / IBM Plex Sans. Brand colours: night `#0a1128`, navy `#16244a`, gold `#d4af37`, pearl `#f4efe6`.
- Replies to the owner: pure Arabic; any Latin term/path/command on its own line in a code block.

### Deployment flow
`install.sh` (once, as root) → prints 3 GitHub **secrets** `VPS_HOST`, `VPS_USER=deploy`, `VPS_SSH_KEY` + **variable** `VPS_ENABLED=true` → every push to `main` (plus a monthly run at 03:17 UTC on the 3rd, and manual runs) runs `deploy-vps.yml`: tar sources over SSH to `/opt/saadat`; settings into `backend.env`/`.env` in place via `deploy/ops/setenv.sh` (values on stdin only; a change touches `.recreate-backend`): mail, Google, **GeoIP database**, **push (VAPID) keys**, **Kashier**; then `docker compose build && up -d` (backend recreated when flagged), smoke-test `https://DOMAIN`. `ops.yml` = remote hands (run a command on the VPS from Actions).

### Country detection (geo pricing)
Order in `CountryResolver`: `CF-IPCountry` (Cloudflare; kept first so a later move to Cloudflare just works) → `X-Country` (local/test mocks only) → **GeoIP**: the visitor's public IP looked up in DB-IP's free "IP to Country Lite" MMDB (MaxMind reader `com.maxmind.geoip2:geoip2`) → setting `pricing.default_country`. The client IP is read from the raw request: Caddy is the only ingress and replaces any client-sent `X-Forwarded-For` with the real address, so when the TCP peer is the proxy (private address on the compose network) the last `X-Forwarded-For` hop is the client; any other peer is the client itself. Private/loopback addresses are never looked up; header values are parsed as IP literals only (no DNS). The `deploy-vps.yml` step "geoip database" downloads this month's file on the runner (falls back to last month), checks it (gzip OK, not empty, MaxMind metadata marker) and copies it to `/opt/saadat/geoip/dbip-country-lite.mmdb` only when the checksum differs (temp file + atomic rename). The backend keeps the database in memory and reloads a changed file within 10 minutes (no restart); without the file it behaves exactly as before. Users keep the country stored at their first sign-in (sign-ups before GeoIP have `SA`/source `DEFAULT`; the interpreter can change it). Licence: CC BY 4.0 — the site must show a link "IP geolocation by DB-IP" → https://db-ip.com (owner step below). Known limit: until Cloudflare is in front, a client can still send its own `CF-IPCountry` header (Caddy passes it through); the card-country check on payments (`SUSPICIOUS`) stays the backstop.

### Push notifications (VAPID)
Step "push notification keys" runs `deploy/ops/vapid-keys.sh` on the VPS: when `VAPID_PRIVATE_KEY` in `backend.env` is empty it generates a P-256 key pair with openssl **on the server** (private = 32-byte scalar, public = 65-byte uncompressed point, both base64url without padding — the format of `nl.martijndwars:web-push` and `npx web-push generate-vapid-keys`), writes `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT=mailto:<site mailbox>` and recreates the backend. Existing keys are never replaced (browser subscriptions are bound to the public key). The private key never leaves the server and is never printed; the frontend reads the public key from `GET /api/public/push-key`.

### YouTube channel id
While setting `brand.youtube_channel_id` is empty, the poller fetches the page in `brand.youtube_url` (https on `app.youtube.channel-page-domain` = youtube.com only, redirects checked), takes the `UC…` id the page declares for itself (canonical link, then `externalId`, meta tags, RSS link) and stores it through `SettingsService` (validated, audited `SETTING_UPDATE`, no actor). It tries at most once per `youtube.poll_minutes`; failures are logged and retried. To switch channels later, change `brand.youtube_url` and empty `brand.youtube_channel_id` (it is resolved again).

### Kashier (Egypt, EGP) — one switch
Kashier replaced Paymob on 2026-10-03. Step "kashier settings" writes GitHub secrets `KASHIER_MERCHANT_ID`, `KASHIER_API_KEY` (Payment API Key — the key named `SAADATU-ALDAREIN` in the dashboard), `KASHIER_SECRET_KEY` and the repository variable `KASHIER_MODE` (`test` | `live`, default `test`) into `backend.env` on stdin, and writes `PAYMENTS_MOCK=false` only when the three secrets are set **and** repository variable `PAYMENTS_LIVE` = `true`; otherwise the payment mode is left as it is (it never writes `true` back). No callback to configure in the Kashier dashboard: every payment session carries `serverWebhook = https://saadatu-aldarein.com/api/webhooks/kashier` (signature `x-kashier-signature`, HMAC-SHA256 with the Payment API Key) and `merchantRedirect = https://saadatu-aldarein.com/me/payments`. Test and live keys differ and must match `KASHIER_MODE`. Kashier takes EGP (also USD/EUR/GBP by contract, never SAR); with the mock off, SAR/USD prices still go to the merchant-of-record provider, which is not configured yet (checkout answers 503 `NOT_CONFIGURED`) — only Egypt can pay until it exists.
